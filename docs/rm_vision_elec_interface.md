## 1. 坐标系定义

### 1.1 TF 树总览

```
odom  ──►  gimbal_link  ──►  camera_optical_frame
(世界系)     (云台系)          (相机光学系)
```

当前由静态 TF 模拟，真机上 `odom → gimbal_link` 段换成 IMU/云台编码器动态发布。

### 1.2 各 frame 约定

| frame | 维护方 | 原点 | 轴方向 | 零点/正方向约定 |
|-------|--------|------|--------|-----------------|
| `odom`（世界/里程计系） | 电控（IMU/里程计）或视觉虚拟 | 待定（建议：云台中心投影点 / 车体初始点） | x 前、y 左、z 上（ROS 标准） | 姿态角零位 = 车体初始朝向 |
| `gimbal_link`（云台系） | 电控（云台编码器） | 云台 yaw+pitch 旋转中心 | x 前、y 左、z 上 | **yaw 零点 = 云台机械零位（编码器 0）**；**pitch 零点 = 枪管水平**；yaw 逆时针为正、pitch 上抬为正 |
| `camera_optical_frame`（相机光学系） | 视觉（相机外参标定，A2） | 相机光心 | **x 右、y 下、z 前**（光学系标准，与 gimbal 系不同！） | 相对 `gimbal_link` 的外参由视觉标定提供 |

### 1.3 必须与电控对齐的三个点

1. **`gimbal_link` 的 yaw 零点** = 电控编码器零点。若不对齐，视觉输出的绝对 yaw 会整体偏一个常数。
2. **`gimbal_link` 的 pitch 零点** = 枪管水平。若电控把"枪管水平"定义在编码器 90°，需要换算。
3. **`odom` 系的姿态由谁提供**：真车上如果电控给 IMU 数据，则 `odom` 是动态系；如果电控不提供，视觉自己虚拟（固定姿态）——**这个决定 solver 的预测基准**，必须明确。

> ⚠️ 光学系坑（已在 Phase 3 踩过）：`camera_optical_frame` 是 x右/y下/z前，而 `gimbal_link` 是 x前/y左/z上，两者差一个光学系旋转。当前静态 TF 用了 `yaw=-90°, pitch=0, roll=-90°` 修正。**真机接动态 TF 时这条旋转也要保留在相机外参里**。

## 2. 角度语义（视觉 → 电控的输出）

### 2.1 字段定义（当前 `GimbalCmd.msg`）

```text
std_msgs/Header header      # 时间戳，frame_id 建议 = gimbal_link
float64 pitch               # 期望俯仰角（°）
float64 yaw                 # 期望偏航角（°）
float64 yaw_diff            # 与当前云台 yaw 的差值（°）
float64 pitch_diff          # 与当前云台 pitch 的差值（°）
float64 distance            # 到目标距离（m）
bool   fire_advice          # 是否建议开火
```

### 2.2 待确认的核心语义

| 问题 | 选项 | 建议 |
|------|------|------|
| `yaw`/`pitch` 是**绝对角**还是**相对当前云台的增量**？ | 绝对角（相对 odom/gimbal 零位）/ 增量（相对当前朝向） | RoboMaster 常见：视觉输出**期望绝对角度**，电控做闭环；或输出**偏差角**由电控叠加。**必须二选一并一致** |
| 单位 | 度 / 弧度 / int16 定点（0.1°） | 电控常用**度**（当前代码就是度） |
| yaw 正方向 | 逆时针为正 / 顺时针为正 | 与电控编码器方向一致 |
| pitch 正方向 | 上抬为正 / 下压为正 | 与电控一致，通常上抬为正 |
| 限位处理 | 超限截断 / 给边界值 / 置 fire_advice=false | 建议：超限截断 + 不触发开火 |
| `yaw_diff`/`pitch_diff` 是否需要 | 电控是否用差值闭环 | 当前代码同时给绝对角和差值，电控按需取 |

### 2.3 约定建议（默认值，供对齐用）

- `yaw`/`pitch`：**期望绝对角度，单位度**
- 正方向：**yaw 逆时针为正、pitch 上抬为正**
- 发送时同时给 `yaw_diff`/`pitch_diff`（方便电控做速度环/增量式）
- 未检测到目标时：`yaw=0, pitch=0, distance=-1, fire_advice=false`

## 3. 开火决策

### 3.1 `fire_advice` 语义

- **是"建议"不是"命令"**：视觉只负责判断"瞄准偏差已进入射击窗口"，是否真的扣扳机由电控决定（受弹仓余量、射速上限、保险开关、裁判系统规则约束）。
- 触发条件（当前 solver `isOnTarget`）：`|yaw_diff| < 射击窗口` 且 `|pitch_diff| < 射击窗口`，其中窗口 = `max(atan2(装甲板半宽/2, distance), 1°)`。
- 离开窗口立即置 `false`。

### 3.2 与电控的约定点

| 项 | 内容 |
|----|------|
| 谁最终开火 | 电控（视觉只发建议位） |
| 触发权限 | 电控需自行判断弹仓/射速/保险，视觉的 `fire_advice=true` 只是"允许开火窗口" |
| 开火间隔 | 电控侧限速（如 15 发/s），视觉不负责 |
| 射击窗口大小 | 可调（`solver` 参数），默认 ±1°，实车按命中率调 |

## 4. 通信协议（串口帧格式，Phase 5 前细化）

> 当前视频模拟无串口。以下为**草案占位**，接串口时按电控串口协议填充。

### 4.1 建议帧格式（视觉 → 电控）

```
[帧头 0xAA 0x55] [长度] [yaw(int16@0.1°) | pitch(int16@0.1°) | distance(uint16@cm) | fire_advice(0/1) | mode] [CRC16]
```

| 字段 | 类型 | 说明 |
|------|------|------|
| 帧头 | 0xAA 0x55 | 帧同步 |
| 长度 | uint8 | 数据段长度 |
| yaw | int16 | 0.1° 定点，单位与第 2 节一致 |
| pitch | int16 | 0.1° 定点 |
| distance | uint16 | cm |
| fire_advice | uint8 | 0/1 |
| mode | uint8 | 自瞄红/蓝等（见第 6 节） |
| CRC16 | uint16 | 校验，高位在前 |

### 4.2 必须与电控确认

- 帧头/帧尾、CRC 算法（MODBUS 还是自定义）
- 字节序（小端为主）、定点精度（0.1° 还是 0.01°）
- 发送频率（建议跟检测帧率：30~60Hz）
- 心跳：电控侧 N 秒没收到帧判视觉掉线 → 云台归中/锁住

## 5. 反馈链路（电控 → 视觉）

### 5.1 电控回读内容

| 数据 | 用途 |
|------|------|
| 云台当前实际 yaw/pitch（编码器值） | ① 闭环校正 ② `prediction_delay` 精确标定 ③ 判断 `fire_advice` 是否真的"到位" |
| 车体速度（线速度/角速度） | 补偿车体运动（小陀螺/底盘跟随） |
| IMU 姿态（roll/pitch/yaw） | 动态更新 `odom` 系（第 1.3 节） |
| 弹仓余量 / 发射状态 | 开火决策辅助 |

### 5.2 反馈帧格式（草案）

```
[帧头] [长度] [cur_yaw(int16) | cur_pitch(int16) | chassis_vx | chassis_vyaw | imu_roll | imu_pitch | imu_yaw] [CRC16]
```

### 5.3 约定点

- 反馈频率（建议与视觉发送同频或更高，如 100Hz）
- 编码器零点与第 1.3 节的 `gimbal_link` 零点一致
- IMU 数据帧定义（角度还是角速度，需明确）

## 6. 模式 / 状态机

### 6.1 当前 `SetMode.srv` 定义

```text
uint8 mode
  # 0: 自瞄红  1: 自瞄蓝
  # 2: 小符红  3: 小符蓝  4: 大符红  5: 大符蓝
---
bool success
string message
```

### 6.2 约定点

| 项 | 内容 |
|----|------|
| 自瞄开关 | 谁触发：视觉默认开 / 电控指令 / 裁判系统下发 |
| 敌我颜色切换 | 视觉自动识别（当前 `set_mode` 手动），还是电控/裁判系统下发？建议真机由裁判系统颜色下发，视觉跟随 |
| 模式枚举 | 上述 0~5 是否与电控/裁判系统的模式一致，需对齐 |
| 掉线/降级 | 视觉掉线 → 电控切手动/归中；颜色未知 → 不触发开火 |

## 7. 补充约定（六类之外，但建议一起定）

### 7.1 时序与同步
- 视觉帧率（检测 ~30Hz）与电控控制周期（如 1kHz）不匹配 → 电控做插值，视觉保证时间戳一致
- `header.stamp` 用哪路时钟：建议用视觉系统时间，电控不依赖视觉时间戳（或统一用同一时间源）

### 7.2 调试期约定（非正式协议）
- 视觉侧日志目录 `~/fyt2024-log/`，可 `ros2 param set` 实时调参（detector 支持动态参数）
- 调试期先用话题（`/armor_solver/cmd_gimbal`）代替串口，确认角度正确后再接串口
- 联调工具：`ros2 topic echo /armor_solver/cmd_gimbal` / `target` / `measurement`

### 7.3 故障与降级策略
| 场景 | 视觉行为 |
|------|---------|
| 检测到目标但跟踪不稳定 | `tracking=false`，不输出开火建议 |
| 无目标 | `distance=-1, fire_advice=false` |
| 云台角度异常（TF 丢失） | 不输出角度，打错误日志 |
| 颜色未知/双方混用 | 不触发开火 |

### 7.4 版本管理
- 本文档随代码走 git，改动记录在文末变更表
- 协议字段增删 → 同步更新 `rm_interfaces` 消息 + 本文档 + 电控端解析
